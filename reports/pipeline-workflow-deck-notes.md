## Slide 2 — The words used on every slide

**On the slide**

*Nothing else is assumed. Terms that belong to a single way are defined on that way's overview slide.*

| Term | Plain meaning |
|---|---|
| RNA matrix (scRNA-seq) | genes × cells; which genes each cell is transcribing |
| ATAC matrix (scATAC-seq) | peaks × cells; which DNA is open in each cell |
| multiome | RNA and ATAC measured in the same cell |
| embedding | ≈30 numbers per cell, so cells can be compared by distance |
| integration | one shared embedding for cells measured different ways |
| imputation | filling in a measurement a cell does not have |
| gene activity | one score per gene per cell, from open chromatin near that gene |
| peak–gene link | a scored candidate enhancer → gene connection |
| GRN matrix | TFs × genes; each entry is the weight of that edge |
| edge weight (importance) | how much a TF helped predict a target; a rank, not a p-value |
| regulon | a TF plus the genes it drives, scored per cell |
| metacell / pseudobulk | a group of cells summed into one column, to raise signal |

**Speaker notes**

> Twelve terms, and everything after this slide uses only these. Two need care. The GRN matrix is a table with transcription factors as rows and genes as columns; the entry is the weight of that edge, and what is written to disk is the same table in sparse form, one row per non-zero entry. An edge weight is a ranking score — how much a TF improved the prediction of a target gene — not a p-value, not a correlation, and it carries no sign. Gene activity is a different object again: one number per gene per cell, computed from open chromatin near that gene, so it lives on the gene axis rather than the regulator axis, and it is not an expression value.

## Slide 3 — Four ways to get from the two matrices to the network

**On the slide**

*Same start, same end; what differs is how many steps are in between and which of them can be checked on their own*

| Way | Steps | What the GRN receives | Main trade |
|---|---|---|---|
| 1 — integrate, impute, infer | 3 | measured RNA + kNN-averaged rows, with a mask saying which is which | every step can be graded on its own; the transfer is bespoke code |
| 2 — one joint model | 2 | imputed RNA from a single fit | best imputation benchmarks; no embedding to gate |
| 3 — gene activity | 3 | measured RNA + accessibility scores on one gene axis | cheapest at scale; mixes two different quantities |
| 4 — aggregate first | 2 | a few thousand pseudo-cells | scale stops mattering; per-cell resolution is gone |

> **HOW EACH WAY IS SHOWN** — overview slide (the steps, with input and output) → one slide of methods per step → one slide of checks per step

**Speaker notes**

> This is the map of the talk. Four ways, and the only column that decides anything is the third one — what the network actually receives. Way 1 hands it a matrix where some rows are measured and some are averages. Way 2 hands it a matrix produced by a single fit. Way 3 hands it two different quantities on one axis. Way 4 hands it a few thousand pseudo-cells. The fourth column is the price of each choice, and it is the column to argue about in the room. Two routes from the earlier survey are deliberately out of scope here: building the network directly from peaks and motifs, and using per-cell TF activity as the regulator side. Both are defensible, and neither fits a pipeline that keeps a gene by cell matrix at its centre.

# Way 1

## Slide 4 — Way 1 — integrate, then impute, then infer

**On the slide**

*Three steps, two artifacts in the middle, and a separate check on each*

**1  INTEGRATE** (RNA + ATAC → H, cells × 30)  →  **2  IMPUTE** (H + measured RNA → X, cells × genes)  →  **3  INFER** (X + TF list → GRN matrix)

| Step | What goes in | What comes out |
|---|---|---|
| 1  integrate | per-dataset PCA (cells × 50), a modality label, a dataset label; paired cells held out | H (cells × 30) + a row-range map per dataset; no genes, no imputation |
| 2  impute | H + the measured RNA matrix on one gene axis + the row indices that need values; answer-key cells excluded | X (cells × genes) + mask (measured vs averaged) + one declared normalization |
| 3  infer | X + mask, the TF list, the target rule, and the cell grouping | GRN matrix: TF × gene importances, written as an edge list, three seeds |

> **THE GRN RECEIVES** — measured RNA rows plus kNN-averaged rows for the ATAC cells, with a mask saying which is which — the booster never sees the mask

**CHOOSE IT WHEN** — you need to know which step failed: every artifact is graded before the next one runs.

**WEAKEST LINK** — the transfer from H to expression: no published implementation and no benchmark behind it.

**SCALE** — optimal transport to about 10⁶ cells; the network step is the cost.

*H and X are the only objects that matter, and both can be inspected without running a network.*

**Speaker notes**

> Way 1 is the sequential route, and it is the one this project implements. Three steps and two artifacts in the middle: H, the joint embedding, which is about thirty numbers per cell; and X, the gene by cell matrix, in which the ATAC rows are averages of measured RNA. Integration never sees genes or peaks, only fifty principal components per cell — the two matrices were reduced separately before this step, because the peaks of one dataset almost never coincide with the peaks of another, and RNA and ATAC share no feature at all. The answer-key cells are paired cells whose RNA is hidden from the imputer and compared against afterwards; frozen means fixed once, never used to fit anything, so the comparison is honest.

## Slide 5 — Way 1 · step 1 — integration: the methods

`WAY 1 · STEP 1 OF 3`

**On the slide**

*Every row returns an embedding — k numbers per cell — or a matching that turns into one in a line of code*

| Method | What you get out | ATAC goes in as | Citation |
|---|---|---|---|
| scSAGA | joint embedding (30-d) + the matching it came from | peaks — raw | Aluru lab, bioRxiv 2026 |
| Pamona | joint embedding + matching; labels cells shared vs dataset-specific | peaks — raw | Cao et al., Bioinformatics 2021 |
| SCOT | matching + one dataset rewritten in the other's feature space — no embedding | peaks — raw | Demetci et al., RECOMB 2020 |
| LIGER | joint embedding + per-dataset gene loadings | gene activity | Welch et al., Cell 2019 |
| Seurat v5 | joint embedding; can also predict the other modality | gene activity | Hao et al., Nat Biotechnol 2024 |
| Harmony | joint embedding, nothing else | gene activity | Korsunsky et al., Nat Methods 2019 |
| scGT | joint embedding | peaks — raw | Bioinformatics 2025 |
| scMODAL | joint embedding, built from a few known linked features | peaks — raw | Nat Commun 2025 |
| scHPGT | joint embedding, built with a regulatory prior | peaks — raw | Bioinformatics 2026 |

*Methods that integrate and impute in one model are on the Way 2 slides — they already return the matrix, so they skip this step's output.*

> **THE INPUT FORM DECIDES THE SHORTLIST** — feed raw peaks and only the transport and manifold methods can run; convert ATAC into gene activity and LIGER, Seurat and Harmony join — but the scores are then flattered, so record which form was used

**Speaker notes**

> These methods do not all return the same kind of object, and the papers use different words for it — aligned embedding, latent, joint latent, shared factors. They all mean the same thing: k numbers per cell, every dataset in one space, so distances between cells mean something. Everything reduces to three outputs: a joint embedding, which step 2 uses directly; a matching, a cell-to-cell probability matrix that must be turned into a neighbour list or an embedding first; or an imputed expression matrix, in which case step 2 is already done. scSAGA gives an embedding of thirty dimensions plus the matching it came from. Pamona gives both and also labels cells as shared or dataset-specific. SCOT is easy to get wrong: it gives a matching plus a barycentric projection that rewrites one dataset in the other's feature space — not a low-dimensional embedding — so it is not a drop-in for a kNN imputer, though if the target domain is RNA the projection is already an expression matrix. LIGER gives an embedding plus per-dataset gene loadings. The third column is the one that decides whether a method can run at all: LIGER, Seurat and Harmony need RNA and ATAC on a shared axis, so ATAC has to be converted into gene activity before they start — a per-gene score summed over each gene's body and promoter, which loses distal enhancers. The transport and manifold methods read the peak matrix as it is.

## Slide 6 — Way 1 · step 1 — integration: the checks

`WAY 1 · STEP 1 OF 3`

**On the slide**

*Four metrics; the first needs paired cells, and it is the strictest*

| Metric | What it asks | Good looks like |
|---|---|---|
| FOSCTTM | for each cell, what fraction of other cells are closer to it than its true cross-modal partner? | 0 is perfect, 0.5 is random; published 0.14–0.16 (MMD-MA), 0.22 (UnionCom) |
| label conservation | are cell types still separated? ARI, NMI, cLISI, silhouette, isolated-label F1 | close to the unintegrated labels, far from a shuffled control |
| batch correction | are the datasets mixed? kBET, iLISI, batch silhouette | improves while the label metrics hold |
| label transfer | can a label learned on the RNA half be assigned to the ATAC half? | above 0.85 on major lineages |

*scIB (Luecken et al., Nat Methods 2022) implements the middle two rows as 14 metrics; report the biology half and the batch half separately.*

> **PASS IF** — FOSCTTM beats the shuffled-partner control, label transfer is above 0.85, and the batch metrics rise while the label metrics hold

**Speaker notes**

> FOSCTTM is simple: for a cell with a known cross-modal partner, what fraction of the other cells are closer to it than that partner is. Perfect is zero, random is about 0.5, and the best published numbers on real paired data are 0.14 to 0.22, so the scale is calibrated before we use it. Report the scIB label and batch halves separately: a single combined score can hide a method that removed batch by destroying biology. The one score deliberately excluded is scSAGA's global alignment score, because it moves with the anchor — it cannot fail.

## Slide 7 — Way 1 · step 2 — imputation: the methods

`WAY 1 · STEP 2 OF 3`

**On the slide**

*Two implementations exist; only one runs in the direction this pipeline needs*

| Method | What it consumes | What it returns | ATAC → RNA? | Citation |
|---|---|---|---|---|
| reverse-imputeKNN (this repo) | H, the measured RNA reference block, and the query rows that need values | one expression row per ATAC cell: a weighted average of its k nearest reference cells | yes — that is what it was written for | run.py, impute() |
| LIGER imputeKNN | H.norm and the reference's peaks | imputed PEAKS for the query cells | no — modal is hard-coded to ATAC | Welch et al., Cell 2019 |

*So the choice in this step is the weighting rule (kNN with exp(−distance), plain kNN, or an optimal-transport plan), k (20 in this repo), and which reference set.*

> **THE GAP** — nothing published takes H and returns gene expression for ATAC cells: LIGER runs the opposite direction, and the transport tools hand back a plan, a projection, labels or factors — the averaging is one line of your code

**Speaker notes**

> This is the honest inventory, and it is short on purpose. Nothing published takes H and hands back gene expression for ATAC-only cells. LIGER is the closest and it runs the wrong direction: its imputeKNN pulls the reference's raw peaks, forces the query dataset to modality ATAC and then normalises peaks — gene to peak, not peak to gene. That is why the step here is called reverse imputeKNN: it is the transpose of LIGER's function, which did not exist. Everything else stops one step earlier. moscot returns a transport plan in a shared latent; SCOT returns a matching and a projection in feature space with no latent at all; Symphony returns query cells placed in the reference space plus labels; MOFA+ returns factors. In each case the weighted average over reference expression is code you write, and it is short. So the real design choice for this step is not which package to install — it is the weighting rule, the number of neighbours, and which reference set. That is a much smaller design space than the method count suggests.

## Slide 8 — Way 1 · step 2 — what averaging does

`WAY 1 · STEP 2 OF 3`

**On the slide**

*The cheap version of this step fails in a predictable way; the mechanism is why the next slide's metrics exist*

1. **Zeros disappear** — an average of 20 cells is rarely zero, so guessed cells look richer than measured ones.
2. **Correlations inflate** — two genes present in the same neighbourhood become correlated because we averaged them, not because a TF links them.
3. **The block becomes detectable** — guessed rows have a different distribution from measured rows, so a model can tell the two apart.
4. **The GRN chases 1–3** — a model that ranks genes by mutual predictability ranks the invented correlations first.

> **VISIBLE SIGNATURE** — a network whose strongest edges are housekeeping genes — ribosomal, mitochondrial, HLA — because those are high and correlated in every neighbourhood

*Measured, not hypothetical: Dijkstra et al., Patterns 2022 (10.1016/j.patter.2021.100414) found inflated gene–gene correlations and altered network structure after imputation.*

**Speaker notes**

> This is the mechanism, and it is why the checks on the next slide matter. Averaging is smoothing, and smoothing manufactures correlation. Whatever truly regulates what, the smoothed matrix insists these genes always appear together, and the boosting model believes it. Housekeeping genes are high and correlated in every neighbourhood, so they surface at the top of the ranking — which is exactly the signature to look for when a network looks wrong. This is not hypothetical: Dijkstra and colleagues measured networks before and after imputation on real data and found inflated gene–gene correlations and altered network structure.

## Slide 9 — Way 1 · step 2 — imputation: the checks

`WAY 1 · STEP 2 OF 3`

**On the slide**

*Lead with pFCS — it is the one metric that measures what step 3 actually reads*

| Metric | What it asks | Source, and how it was used | Good looks like |
|---|---|---|---|
| pFCS | is the gene–gene correlation structure preserved? Pearson of the two correlation matrices over the top-100 variable genes | Liu et al., Nat Methods 2025 — one of their three data-structure metrics | high, and above the control |
| MSE | how far is the guess from the hidden value? | Liu et al. 2025, as sMSE — ranks methods on held-out truth | low, and below the control |
| pDES | are differential-expression statistics preserved? (limma, per cell type) | Liu et al. 2025 — DE statistics recomputed after imputation | high |
| gene-wise ρ | per-gene Pearson or Spearman against the hidden RNA | Polarbear 2022 and BABEL 2021, on SNARE-seq — per-gene Pearson | 0.155–0.22; the published ATAC → RNA ceiling |
| densification | nonzero fraction of guessed rows vs measured rows | Andrews & Hemberg 2019 — zeros created, and the false positives after | no inflation |
| downstream | 5 classification and 5 clustering metrics on the imputed matrix | Liu et al. 2025 — classifier and clustering on the imputed data | as the benchmark defines |

*scIMC (NAR 2022) and the scTranslation benchmark (SIGKDD 2026) are ready-made harnesses for this whole list.*

> **NEGATIVE CONTROL** — repeat the whole measurement with randomized neighbours; if the control scores as well, the metric is describing the data, not the imputation

**Speaker notes**

> Lead with pFCS. It asks the exact question the next step depends on: after imputation, do genes still correlate the way they really correlate? A blurred matrix can have low MSE and still destroy correlation structure, and correlation structure is the only thing the network model reads. Every metric here needs held-out paired cells — cells measured both ways whose RNA was hidden before the imputer ran; there is no truth behind an ATAC-only row. On the source column: four rows come as a set from the imputation task of Liu et al. 2025, which is why the deck uses their names — sMSE, pFCS and pDES are the three data-structure metrics, and the downstream block is five classification and five clustering metrics computed on the imputed matrix. Reusing the names means our numbers sit next to published ones instead of beside them. gene-wise ρ is the one row calibrated on data of exactly this kind: Polarbear and BABEL report per-gene Pearson for ATAC to RNA translation on SNARE-seq, and 0.155 to 0.22 is where they land — which is how a reported 0.9 reads as a leak rather than a triumph. Densification comes from Andrews and Hemberg, who counted the zeros imputation creates and the false positives that follow; it is a diagnostic, not a score, which is why no target is set for it. And the shuffled-neighbour control is their permuted-dataset design borrowed wholesale: run the metric on data known to contain no signal and see what it still reports. It sits in a strip rather than a row because it is the only check that can fail on its own.

## Slide 10 — Way 1 · step 3 — the network: the methods

`WAY 1 · STEP 3 OF 3`

**On the slide**

*The matrix is expression-like, so the methods that fit are the expression-only ones*

| Method | What it does | What you get | Citation |
|---|---|---|---|
| GRNBoost2 (arboreto) | gradient boosting, one regression per target gene | ranked TF→target importances, unsigned | Moerman et al., Bioinformatics 2019 |
| GENIE3 | random-forest importance, one regression per target | ranked TF→target importances | Huynh-Thu et al., PLoS ONE 2010 |
| SCENIC | GRNBoost2 or GENIE3, then motif pruning (RcisTarget) | regulons: a TF + its targets, scored per cell | Aibar et al., Nat Methods 2017 |
| PIDC | partial information decomposition over triplets; no direction | undirected TF–target association | Chan et al., Cell Systems 2017 |
| SCODE | linear ODE along pseudotime, low-rank | signed TF→target coefficients | Matsumoto et al., Bioinformatics 2017 |
| DeepSEM | structural equation model with a linear decoder | directed TF→target weights | Shu et al., Nat Comput Sci 2021 |

*What gets written out is the GRN matrix in sparse form: TF, target, importance — one row per edge, three seeds so the noise floor is measurable.*

> **BASELINE** — GRNBoost2 — geneRNIB (2025) finds simple models match or beat complex ones on this task, so the booster is not the weak link; the matrix is

**Speaker notes**

> The matrix arriving here is expression-like, so the methods that fit are the expression-only ones. GRNBoost2 fits one gradient-boosted regression per target gene and reports which regulators contributed; it takes no target list, so the columns of the matrix are the target list. GENIE3 does the same with random forests and is a useful second opinion because its errors are different. SCENIC wraps either of them and adds motif pruning, which turns a ranked edge list into regulons — a TF plus the genes it drives — and is the right choice if you want a per-cell activity score. PIDC and SCODE come from a different tradition: information decomposition gives no direction, and the linear-ODE model gives signed coefficients but assumes a differentiation trajectory. DeepSEM is the deep-learning entry point and needs many more cells than this dataset has. The chromatin-aware methods — SCENIC+, LINGER, HuMMuS — are out of scope here: they take peaks, so they replace this whole route instead of consuming its input.

## Slide 11 — Way 1 · step 3 — the network: the checks

`WAY 1 · STEP 3 OF 3`

**On the slide**

*AUPRC, not AUROC; and only the top-ranked edges count*

| Metric | What it asks | Good looks like |
|---|---|---|
| AUPRC | of all possible TF→target pairs, how well are the true ones ranked? | above the negative control |
| early precision | precision among the top-ranked edges | the headline metric in BEELINE |
| stability | Jaccard of the top-10k edges across 3 seeds and subsamples | any reported difference must exceed it |
| topology | are hubs and degree structure recovered? | comparable to the planted network |
| perturbation | does the network predict a measured knockout? | positive agreement |
| regulon activity | AUCell score of the top regulons, per cell type | cell-type specific, not global |

*Three truth tiers, following BEELINE (Pratapa et al., Nat Methods 2020): synthetic networks, literature Boolean models, experimental ChIP and knockout.*

> **PASS IF** — differences exceed seed noise, lineage TFs sit in the top edges (PAX5/EBF1→MS4A1 in B cells; SPI1/CEBPA→LYZ in myeloid; TBX21/GNLY in NK), and AUPRC beats the control

**Speaker notes**

> Use AUPRC rather than AUROC: with a few thousand true edges among hundreds of thousands of possible pairs, AUROC looks flattering while AUPRC tells the truth. Score only the top-ranked edges, and report stability before anything else. The booster is stochastic — each split looks at ten percent of the regulators and each tree at ninety percent of the cells — so the same input gives a slightly different network every run. Three seeds, then the overlap of the top ten thousand edges, gives the noise floor: anything smaller than that is not a result. One metric needs a word of explanation: AUCell scores a gene set per cell by where its members rank in that cell's expression, so a regulon score is high only in cells where the regulon's targets are near the top. Truth comes in three tiers, and all three should be reported.

# Way 2

## Slide 12 — Way 2 — one model does both, then infer

**On the slide**

*Two steps: integration happens inside the imputer, so there is no embedding to hand over*

**1  INTEGRATE + DECODE** (RNA matrix + ATAC matrix → trained model → X)  →  **2  GRN INFERENCE** (X + TF list → GRN matrix)

| Step | What goes in | What comes out |
|---|---|---|
| 1  integrate and decode | the RNA matrix and the ATAC matrix, plus a mask of which modality each cell has | a trained model; z, its internal latent (export it only if you want a check); and imputed expression for the ATAC cells |
| 2  grn inference | X — the measured RNA rows stacked with the decoded ATAC rows, one gene axis, one normalization — plus the TF list and the target rule | GRN matrix: TF × gene importances, as an edge list, three seeds |

> **THE GRN RECEIVES** — the same kind of matrix as Way 1 — measured rows plus imputed rows — produced in a single fit rather than two

**CHOOSE IT WHEN** — you want the best published imputation accuracy and the least code to write.

**WEAKEST LINK** — no artifact to gate: export the latent or there is nothing to check before the network runs.

**SCALE** — minibatch training on a GPU; cost grows with cells, not with pairs.

*Paired cells are held out of training for one reason only: they are the answer key that lets the decoded rows be graded. Nothing else in this route can be checked. Ceiling: ATAC → RNA gene-wise Pearson ≈ 0.22 (Polarbear), 0.155 (BABEL) on SNARE-seq.*

**Speaker notes**

> Two boxes, and the first one does both jobs. Box one takes the RNA matrix and the ATAC matrix and learns a model; inside that model every cell is compressed to a short vector of numbers — the latent, written z — which is the same kind of object as H in Way 1, except that it lives inside the model and is never written out. If you export z you can run the FOSCTTM check on it; if you do not, there is nothing between the boxes to examine. The decoder then reads z and produces expression for the cells that had no RNA. What it produces is only those rows: X is the imputed rows stacked underneath the measured RNA rows, on one gene axis, under one normalization, with a mask saying which row is which — and that stacked X is what arboreto receives, cells as rows and genes as columns. One trap: the decoder's output has to be mapped into the same normalization as the measured rows, or the two blocks are separable and the booster learns which block a cell came from rather than biology. On the paired cells: the model does not need them to train, since the mask already says which cells have which modality. They are held out because they are the only answer key for the decoded rows, and this route has no embedding artifact to grade instead — with fully unpaired data the first box cannot be checked at all, and simulation is the only honest test. Two numbers to keep beside the result: about 0.22 gene-wise Pearson is the ceiling for ATAC to RNA, so 0.9 means leakage and 0.05 means nothing was produced.

## Slide 13 — Way 2 · step 1 — the joint model: the methods

`WAY 2 · STEP 1 OF 2`

**On the slide**

*Two methods need no paired cells; every other one in this family does*

| Method | Kind of model | What it takes in | What you get out | Citation |
|---|---|---|---|---|
| MultiVI | joint VAE; a per-cell mask says which modality is missing | raw counts for both — RNA per gene, ATAC per peak — plus the mask. No gene activity. | joint embedding + imputed expression for the ATAC cells | Ashuach et al., Nat Methods 2023 |
| GLUE / scGLUE | VAE aligned through a peak–gene guidance graph | raw counts for both — RNA per gene, ATAC per peak — plus the prior graph. No gene activity. | joint embedding + imputed expression for the ATAC cells | Cao & Gao, Nat Biotechnol 2022 |

*Neither one converts ATAC to gene activity: both read the peak matrix, which is why they can run without a shared gene axis. Left out, and why: scGALA (anchor pairs), Polarbear (a paired subset), BABEL and Cisformer (pairs inside the checkpoint), scButterfly (pseudo-pairs from labels), scDCT (co-assay training), scGPT (no ATAC path).*

> **WHAT STEP 2 NEEDS** — a joint embedding to look up neighbours in, and one gene-by-cell block of imputed expression for the ATAC cells — both methods return both

**Speaker notes**

> Two methods, because these two are the only ones that run when the RNA and ATAC matrices share no cells — and that is the case this pipeline is built for: the ATAC cells that need values were never measured for RNA, so a method that expects a paired cell to learn from has nothing to learn from. MultiVI is built for exactly this shape of data: every cell carries a mask saying what was measured, so a cell can be RNA-only, ATAC-only or both, and one latent is learned for all of them; whatever a cell is missing gets decoded. GLUE does the same job from the other side — a graph of peak-to-gene links supplies the correspondence the data does not have, so the two modalities are aligned through the prior rather than through shared cells — and that prior has to be built from paired data somewhere, either yours or a public multiome reference, which is the honest cost of this option. On the input column: neither method asks you to convert ATAC into gene activity. Both read the peak matrix as counts, which is why they can run at all when the two matrices share no gene axis; the gene-level information reaches GLUE through the prior graph and reaches MultiVI through the decoder. That is the opposite of Way 1's LIGER, Seurat and Harmony, which do need gene activity before they will start. Both return the same two objects, and the table uses one phrase for the second on purpose. A joint embedding is the k numbers per cell the model places every cell at — the same object as H in Way 1, except that here it lives inside the model and is only written out if you export it; that is the z on the previous slide. Imputed expression for the ATAC cells is one gene-by-cell block on the same gene axis as the measured RNA, holding the values those cells would have had. Stack that block under the measured rows, one normalization, and you have X. Everything else is left out for a reason: scGALA wants anchor pairs, Polarbear a small paired subset to train its translator, BABEL and Cisformer carry pairs inside their checkpoints, scButterfly manufactures pseudo-pairs from cell-type labels, and scDCT trains on co-assay cells. scGPT has no ATAC input path at all — checked in this repo's own code review.

## Slide 14 — Way 2 · step 1 — the joint model: the checks

`WAY 2 · STEP 1 OF 2`

**On the slide**

*The Way 1 checks apply, on paired cells masked before fitting — but only if the latent was exported*

| Metric | What it asks | Good looks like |
|---|---|---|
| held-out MSE | how far is the decoded expression from the hidden RNA? | low, and clearly below the shuffled control |
| pFCS | is the gene–gene correlation structure preserved? | high, and clearly above the control |
| gene-wise ρ | per-gene Pearson or Spearman against the hidden RNA | 0.155–0.22; higher suggests leakage |
| FOSCTTM on the exported z | is each cell nearest its true partner in the model's own space? | 0.14–0.22 if z was saved — otherwise this check does not exist |
| run-to-run agreement | do two fits give the same network? | reported differences must exceed it |

> **WHAT TO WATCH** — the latent is not identifiable: retraining reorders it, so every check is recomputed per fit, and hyperparameters move the result more than the data does

**Speaker notes**

> The Way 1 checks still apply, with one precondition: you have to save the latent. If the model does not write z, there is no step-1 gate at all, and the only evidence that the alignment worked is that the imputation scored well — which conflates two failures. Two extra controls are specific to this way. First, mask paired cells before fitting and grade the decoded values against the hidden RNA, not against ATAC-only rows, which have no truth. Second, retrain: the latent is not identifiable, so a second seed reorders it, and every check has to be recomputed per fit.

## Slide 15 — Way 2 · step 2 — the network: the checks

`WAY 2 · STEP 2 OF 2`

**On the slide**

*Same methods as Way 1 step 3; what changes is the control this route owes*

| Method | What it does | Citation |
|---|---|---|
| GRNBoost2 | the baseline: one boosted regression per target gene | Moerman et al., 2019 |
| SCENIC | adds motif pruning, so the output is regulons, not edges | Aibar et al., 2017 |
| GENIE3 | a second opinion with different errors — run both, compare the top 10k | Huynh-Thu et al., 2010 |

**HOW THE STEP IS CHECKED**

- AUPRC and early precision against cell-type-matched truth.
- Stability: Jaccard of the top-10k edges across three seeds.
- Lineage TFs present in the top edges of every cell-type network.
- Way-2-only control A: a network built from the imputed rows alone must be clearly worse — otherwise the imputation is adding noise, not signal.
- Way-2-only control B: two fits, two latents, measure edge overlap.

> **WHAT TO WATCH** — a network built on decoded rows inherits the decoder's bias; the imputed-only control is the only test that separates the decoder's structure from biology

**Speaker notes**

> The network step itself is identical to Way 1 step 3 — the same booster, the same metrics — because the matrix arriving here is the same shape and the same kind of number. What changes is the control you owe it. In Way 1 the imputed rows were produced by a short, inspectable average; here they were produced by a decoder, whose biases are opaque. So the network has to be shown to be better than a network built only from the imputed rows, and it has to be shown to be stable across two fits, not just across three seeds of one fit.

# Way 3

## Slide 16 — Way 3 — gene activity, then infer

**On the slide**

*No translation and no imputation: ATAC is projected onto the gene axis and stacked next to measured RNA*

**1  SCORE** (peaks + annotation → gene activity)  →  **2  STACK + MASK** (RNA + activity → X + mask)  →  **3  INFER** (X + TF list → GRN matrix)

| Step | What goes in | What comes out |
|---|---|---|
| 1  score | the ATAC peak matrix of every ATAC dataset — i of them, nᵢ cells each — plus gene annotation for one common set of G genes | gene activity: (Σᵢ nᵢ) × G — each dataset scored on its own, then placed side by side along cells |
| 2  stack and mask | gene activity + every measured RNA dataset, all on the same G genes, under one normalization per dataset; the RNA side contributes n_RNA rows in total | X: (Σᵢ nᵢ + n_RNA) × G, plus a mask of the same shape, row by row measured or scored |
| 3  infer | X + mask, the TF list, the target rule, the cell grouping; T regulators | GRN matrix: T × G, written as an edge list |

> **THE GRN RECEIVES** — measured RNA plus accessibility-derived scores on the same gene axis — a different quantity, not a worse measurement of the same one

**CHOOSE IT WHEN** — you need scale with no custom code: a sparse matrix multiply, linear in cells.

**WEAKEST LINK** — the two blocks are different quantities, and the model prefers whichever has more variance.

**SCALE** — ArchR and Signac both scale with sparse matrices; no OT, no deep model.

*The arithmetic, for three ATAC and four RNA datasets: step 1 gives (n₁+n₂+n₃) × G, step 2 gives (n₁+…+n₇) × G, step 3 gives T × G — where G is the genes present in every one of the seven, matched on stable IDs. Row order is fixed when the blocks are stacked.*

**Speaker notes**

> Way 3 deletes the hard step instead of solving it. ATAC goes to per-gene scores using the annotation — sum the open chromatin across a gene's body and promoter, optionally adding distal regions — then those scores are stacked with measured RNA on the same gene axis, a mask records which rows are scores, and the network runs on the whole matrix. Nothing is imputed, so nothing can be imputed wrongly. But the two blocks are not the same quantity: one is transcript abundance, the other is accessibility near a gene, and a model given both will lean on whichever block has more variance. Saying that out loud is the entire job of the mask here. The dimensions are worth saying slowly, because the row count is where people lose track. Call the number of ATAC datasets i and their cell counts n-one to n-i, the measured RNA cells n-RNA, the genes on the shared axis G, and the regulators T. Step one is applied to each ATAC dataset separately — the annotation does not change — so its output is the ATAC blocks side by side: sum of n-i rows by G columns. Step two adds the RNA rows underneath and changes nothing else, so X is sum of n-i plus n-RNA rows by G columns, with a mask the same shape. Step three consumes X and returns T by G. Three things have to be fixed for any of that to add up: G must be one set of genes for every dataset, so if the ATAC datasets were quantified against different annotations they have to be re-scored onto one; the order of the blocks must be written down once, because the mask and the cell-type labels are indexed by row; and the scoring tools hand back genes by cells, so the matrix is transposed once at that boundary and never again. G is the part people get wrong once there is more than one dataset of either kind. Three ATAC datasets and four RNA datasets carry seven gene lists; G is the intersection of all seven, matched on stable gene identifiers such as Ensembl IDs rather than symbols, because symbols alias and repeat across builds. The ATAC side barely constrains it — you re-score each ATAC dataset onto the chosen annotation, so in practice the RNA intersection sets G, and the intersection is what shrinks with every dataset added. Report G, the number of genes each dataset cost, and whether the loss is concentrated in one dataset, since that usually means a different annotation build rather than real biology. Two consequences for the rest of the step: the mask needs a second field, the dataset each row came from, because pooled rows from four labs are not comparable in the way rows from one are; and the network should be run per RNA dataset once as a check, since the edge overlap between them is a batch effect you can measure before you attribute anything to biology.

## Slide 17 — Way 3 · step 1 — gene activity: the methods

`WAY 3 · STEP 1 OF 3`

**On the slide**

*Two scorers, and one way to add distal enhancers instead of using a fixed window*

| Method | What it computes | What you get out | Citation |
|---|---|---|---|
| ArchR addGeneScoreMatrix | accessibility weighted across the gene body and promoter, distance-decayed | gene activity, genes × cells | Granja et al., Nat Genet 2021 |
| Signac GeneActivity | promoter extended by 2 kb; works from fragments or from a peak matrix | gene activity, genes × cells | Stuart et al., Nat Methods 2021 |
| ArchR addPeak2GeneLinks | distal enhancers added by accessibility correlation instead of a fixed window | peak → gene links, to be folded into the score | Granja et al., Nat Genet 2021 |

*Correlate the scores against measured RNA on paired cells before using them: expect a modest correlation, not a high one.*

> **THE WINDOW IS THE DECISION** — promoter-only is conservative and misses enhancers; body plus a wide window catches them and also catches neighbouring genes — record the window, because scores are not comparable across windows

**Speaker notes**

> ArchR and Signac both compute gene scores; the difference is the window. Signac extends the promoter by two kilobases and effectively scores the promoter, which is conservative and misses enhancers. ArchR weights accessibility across the gene body plus a distance-decayed upstream window, and can add peak–gene links if you want distal enhancers rather than a fixed window. Cicero is different in kind and stays out of scope here: it gives co-accessibility between peaks, which is a link set rather than a per-gene score. The window is the design decision, and it has to be recorded, because scores are not comparable across windows.

## Slide 18 — Way 3 · step 1 — gene activity: the checks

`WAY 3 · STEP 1 OF 3`

**On the slide**

*Measure the substitution honestly, on the cells where both measurements exist*

| Metric | What it asks | Good looks like |
|---|---|---|
| gene activity vs measured RNA | per-gene Pearson on paired cells | modest, not high — a high value suggests the window was tuned on the answer |
| block distribution match | mean, variance and nonzero fraction, scored rows vs measured rows | no systematic shift |
| peak quality | FRiP and TSS enrichment per cell | passing cells only; drop the rest before scoring |
| does it add or dilute | GRN on mixed rows minus GRN on RNA-only rows | a positive delta; a negative delta means drop the ATAC rows |

> **WHAT TO WATCH** — a scored row is not a noisy expression row — it is a different quantity, so the columns of the matrix no longer mean the same thing for every row

**Speaker notes**

> Start by measuring the substitution honestly, on the cells where both measurements exist. If gene activity correlates with measured RNA at 0.8, that is not good news — it usually means the window was tuned on the answer, or that the score is mostly promoter signal for the same gene. A modest correlation is the expected result. Then check that the two blocks have comparable distributions after one normalization, and finally ask the only question that matters: does adding the scored rows help or dilute the network. That last number is the one to report, and it can be negative.

## Slide 19 — Way 3 · step 2 — stacking and masking

`WAY 3 · STEP 2 OF 3`

**On the slide**

*Bookkeeping that decides whether the network learns biology or block membership*

| Check | What it asks | Good looks like |
|---|---|---|
| block separability | train a classifier to tell scored rows from measured rows | chance level only — above chance means a shortcut exists |
| per-gene shift | mean, variance and nonzero fraction per gene, block A vs the measured-row distribution | no systematic shift after normalization |
| row accounting | how many rows are scored vs measured | recorded; a small ATAC block cannot carry the network |
| axis identity | are the gene sets identical, and is the order fixed? | byte-identical across runs |

*What the step produces: X (cells × genes, float32), mask (same shape, bool), genes.txt, and norm.txt with the single declared transform.*

> **THE MASK IS THE DELIVERABLE** — without it nobody downstream can point at a row and say 'that one is a score' — so nobody can ask whether the ATAC rows helped

**Speaker notes**

> This step is bookkeeping, and it is where the route is won or lost. One gene axis: either the intersection of the two gene sets or the RNA set, and it is recorded once. One normalization: exactly one declared transform, for example log1p of counts per ten thousand, applied so that measured and scored rows sit on the same scale — if the scoring tool outputs something else, it has to be mapped into that space. Then the rows are stacked and the mask is written, true where the value was measured and false where it was scored. The quick test is a classifier: if a model can tell scored rows from measured rows above chance, the blocks are separable, and the network can learn block membership instead of biology.

## Slide 20 — Way 3 · step 3 — the network: the checks

`WAY 3 · STEP 3 OF 3`

**On the slide**

*Same methods as Way 1; the extra control is a network without the scored rows*

| Method | What it does | Citation |
|---|---|---|
| GRNBoost2 | baseline; one boosted regression per target gene | Moerman et al., 2019 |
| SCENIC | adds motif pruning, so the output is regulons | Aibar et al., 2017 |
| GENIE3 | second opinion with different errors | Huynh-Thu et al., 2010 |

**HOW THE STEP IS CHECKED**

- AUPRC and early precision on cell-type-matched truth.
- Delta against the RNA-only network — report the sign.
- Stability: drop the scored rows, re-run, compare the top-10k edges.
- Lineage TFs present in the top edges of every cell-type network.

> **WHAT TO WATCH** — in a mixed matrix a TF→target edge can be driven by the scored block alone; the RNA-only network is the reference against which every claim is made

**Speaker notes**

> The network step is the same family as Way 1, with one addition that matters more than the method choice: run it twice, once with the scored rows and once without. The RNA-only network is the reference, not a variant, because it is the only way to say whether the ATAC rows contributed. A mixed matrix also makes 'top edge' ambiguous — an edge can be driven entirely by the scored block, since that block can have more variance than the measured one.

# Way 4

## Slide 21 — Way 4 — aggregate cells first, then infer

**On the slide**

*Change the unit of inference rather than the method: a few thousand pseudo-cells instead of 10⁵ single cells*

**1  AGGREGATE** (X + a cell→group map → pseudo-cells)  →  **2  INFER** (pseudo-cells + TF list → GRN matrix)

| Step | What goes in | What comes out |
|---|---|---|
| 1  aggregate | any cell × gene matrix (from Way 1, 2 or 3) + a cell → group assignment — metacell, cell type, or donor | pseudo-cells (10³–10⁴ columns) + their labels and sizes |
| 2  infer | the pseudo-cell matrix, the TF list, the target rule | GRN matrix: TF × gene importances, at population level |

> **THE GRN RECEIVES** — a few thousand pseudo-cells rather than 10⁵ single cells — dropout is reduced and the network is far more reproducible

**CHOOSE IT WHEN** — you need scale, or a network you have to defend as reproducible.

**WEAKEST LINK** — the unit changed: nothing here is comparable to a per-cell network.

**SCALE** — linear, and the cheapest route in the deck; the network step takes minutes.

*This step inherits the earlier choice: if the input matrix came from Way 1, the aggregation is done on kNN-averaged rows as well.*

**Speaker notes**

> Way 4 changes the unit of inference instead of the method. Take any cell by gene matrix — from Way 1, 2 or 3 — plus an assignment of cells to groups, and aggregate. What comes out is a few thousand pseudo-cells, and everything downstream is cheap. This is the route that makes scale a non-issue and it has the best evidence for reproducibility, because population-level networks are far more stable than single-cell ones. The price is explicit: the numbers are not comparable to a per-cell network, and a rare population can disappear into an aggregation entirely.

## Slide 22 — Way 4 · step 1 — aggregation: the methods

`WAY 4 · STEP 1 OF 2`

**On the slide**

*Three ways to replace single cells with groups, with different notions of what a group is*

| Method | What it does | What you get out | Citation |
|---|---|---|---|
| SEACells | archetypal-cell decomposition of a low-dimensional embedding, soft membership | metacells + a membership matrix | Persad et al., Nat Biotechnol 2023 |
| MetaCell | balanced kNN-graph partitioning with a size target | metacells, hard and disjoint | Baran et al., Genome Biol 2019 |
| pseudobulk | sum raw counts per cell type × donor | one column per group, with a donor dimension | standard practice |

*Run the network on the pseudo-cells and, once, on the single cells — the difference is the price of aggregation, and it is the number to report.*

> **WHAT CHANGES** — the aggregation is a model too: a bad partition silently merges two cell states, and the network for both is then wrong in the same way

**Speaker notes**

> SEACells builds archetypal cells from a low-dimensional embedding and returns a soft membership matrix, which is why it is the default when you want to keep some per-cell structure. MetaCell partitions a kNN graph into balanced groups with a size target and returns hard, disjoint metacells, which is simpler to defend. Pseudobulk is the simplest version of all and needs a donor or replicate column: sum raw counts per cell type per donor. Nothing here needs the ATAC side; whatever matrix Way 1, 2 or 3 produced is the input, so this step also inherits that way's assumptions.

## Slide 23 — Way 4 · step 1 — aggregation: the checks

`WAY 4 · STEP 1 OF 2`

**On the slide**

*Check the units before checking the network*

| Metric | What it asks | Good looks like |
|---|---|---|
| metacell purity | is each metacell one cell state? | high purity; check the mixing, not the mean |
| partition stability | re-run the aggregation — same units? | high overlap across seeds and subsamples |
| group size distribution | are groups balanced, and is any cell type missing? | no population lost to underflow |
| marker recovery | do group-level pseudobulks recover canonical markers? | the expected markers present in each group |

> **WHAT TO WATCH** — a metacell averages over its members by construction, so any check that looks only at the average will pass even when the partition is wrong

**Speaker notes**

> The checks are about the aggregation itself, not about the network. Is each metacell one cell state? Check the mixing, not the mean — a metacell that mixes two cell types looks fine in an average and destroys both. Do you get the same units when you re-run? Are any populations missing, because they were too small to form a group? And do the group-level pseudobulks recover the canonical markers you expect? All four are cheap and all four should be reported before a network is built on top.

## Slide 24 — Way 4 · step 2 — the network: the checks

`WAY 4 · STEP 2 OF 2`

**On the slide**

*On a few thousand columns the method is cheap, so run more than one*

| Method | What it does | Citation |
|---|---|---|
| GRNBoost2 | baseline; minutes on 10³–10⁴ columns | Moerman et al., 2019 |
| GENIE3 | second opinion with different errors | Huynh-Thu et al., 2010 |
| SCENIC | adds motif pruning; regulons per group | Aibar et al., 2017 |

**HOW THE STEP IS CHECKED**

- Stability across partitions, not just across seeds.

## Slide 25 — How to choose between the ways

**On the slide**

*Name the binding constraint first; the ways also compose*

| If the binding constraint is… | Take | Because |
|---|---|---|
| per-step attributability | way 1 | the only route with an embedding artifact and a separate transfer step |
| raw imputation accuracy | way 2 | end-to-end training beats a translation bolted onto a fixed embedding |
| scale, with no custom code | way 3 or 4 | a sparse matrix multiply or an aggregation; neither needs optimal transport |
| distrust of imputed gene expression | way 3 | the ATAC rows are accessibility scores, not imputed expression |
| a cheap second opinion on way 1 | way 3 or 4 | both reuse way 1's matrix, so they act as controls on it |

*Way 1 is the only route where every step can be graded independently, which is why it is described in most detail. That is a design trade, not a claim that it is the most accurate.*

> **THEY COMPOSE** — gene activity for the ATAC rows, aggregated into metacells: no transport, no deep model, no bespoke transfer

**Speaker notes**

> The decision rule is to name the binding constraint first, before comparing methods. If it is attributability, Way 1 is the only option. If it is imputation accuracy, Way 2 wins on benchmarks. If it is scale with no custom code, Ways 3 and 4 are linear and need no optimal transport. If what you distrust is imputed gene expression, Way 3 never produces any. And the ways compose: gene activity for the ATAC rows, aggregated into metacells, needs no transport, no deep model and no bespoke transfer — that combination is the natural candidate at a million cells. Ways 3 and 4 also double as controls on Way 1, because both consume the matrix Way 1 produced.

## Slide 27 — Each gate protects the next step from one failure

**On the slide**

*The gates are what make this a pipeline rather than a sequence of scripts*

| Gate | Protects | From what |
|---|---|---|
| 1 — FOSCTTM + scIB | the imputation | a lookup space where 'nearest neighbour' means nothing, so the average is meaningless |
| 2 — pFCS + MSE + ρ | the network | a matrix that is confidently wrong: guessed rows are structured, so the network is structured and wrong |
| 3 — stability + lineage TFs + AUPRC | the conclusion | validating noise |
| end-to-end — simulation | the design | steps that were never shown to work together |

> **THE DIFFERENCE** — every way except Way 1 collapses gates 1 and 2 into one, because none of them has an embedding artifact and a separate averaging step — fewer places to stop, and fewer failures caught

**Speaker notes**

> A sequence is four scripts in a row. A pipeline is a sequence where each output has been shown good enough to be the next step's input, and the gates are the difference. The last row is the one people skip: nothing in a per-step gate proves the steps work together, which is why the simulated route has to be graded end to end. Ways 2, 3 and 4 collapse the first two gates into one, because none of them has an embedding artifact and a separate averaging step — that is the real cost of the shorter route: fewer places to stop and check.
